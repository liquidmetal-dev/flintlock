# AGENTS.md

Guidance for AI coding agents working in this repository. Humans should read
[`CONTRIBUTING.md`](CONTRIBUTING.md) — it is the full, authoritative guide. This
file is the agent-facing digest and defers to it on any conflict.

## Project overview

`flintlock` is a Go service for creating and managing microVMs over a gRPC
API, using either [Firecracker](https://firecracker-microvm.github.io/) or
[Cloud Hypervisor](https://www.cloudhypervisor.org/) as the underlying VMM.
The daemon is `flintlockd`.

Key directories:

- `cmd/` — binary entrypoints (`flintlockd`, metrics)
- `core/` — domain logic (ports, application services)
- `internal/`, `pkg/` — implementation packages
- `api/` — protobuf/gRPC definitions
- `client/` — generated/consumer client code
- `test/` — e2e and integration tests
- `userdocs/` — documentation site (npm)
- `hack/` — scripts and build tooling

### Hypervisor providers

The active provider is selected in `infrastructure/microvm/providers.go`
based on which binary path is configured (`FirecrackerBin` /
`CloudHypervisorBin`); both can be enabled at once.

- `infrastructure/microvm/firecracker/` — Firecracker driver
- `infrastructure/microvm/cloudhypervisor/` — Cloud Hypervisor driver
- `pkg/cloudhypervisor/` — low-level HTTP client for Cloud Hypervisor's
  REST/socket API (Firecracker has no equivalent since it's driven by a
  config file rather than an HTTP API)
- `infrastructure/microvm/shared/` — logic shared between both drivers

Cloud Hypervisor's driver advertises extra capabilities (macvtap, virtiofs)
not currently supported by the Firecracker driver — see each provider's
`Capabilities()`.

## Build, test, lint

Run from the repo root:

- `make build` — build the binaries
- `make test` — run unit tests
- `make lint` — run golangci-lint (config in `.golangci.yml`)
- `make generate` — regenerate mocks, protobuf, and DI wiring; run this after
  changing anything under `api/` or any mocked interface
- `make test-e2e` — e2e tests (require KVM + Firecracker; normally CI only)

Every commit must be compilable with `make test` passing.

## Commit & PR rules

- **Keep changes small.** One focused concern per PR and per commit. Split
  unrelated work into separate PRs rather than bundling it.
- **No `Co-Authored-By:` trailers** in commit messages.
- **No agent or AI names** (e.g. Claude, Codex, "generated by …") anywhere in
  commit messages, commit titles, or PR titles.
- **No agent footers** (`Co-Authored-By:`, session/task links, "Generated
  with …" badges, etc.) in PR descriptions either — the rules above apply to
  PR bodies, not just commits and titles.
- **Commit messages must follow [Conventional Commits](https://www.conventionalcommits.org/)**
  (see CONTRIBUTING.md § *Commit message formatting* for the full type list):
  - Header: `<type>[optional scope]: <subject>` (e.g.
    `feat(cloudhypervisor): add virtiofs support`), subject ≤ 70 chars.
  - Blank line, then a body wrapped at ~80 chars describing *why* and *how*.
- **Sign off** every commit for DCO (`Signed-off-by:`, i.e. `git commit -s`).
- Squash noise commits (`fix stuff`, `wip`) before requesting review.
- **PR title** must itself be a valid Conventional Commit header — it is
  checked in CI and lands in the release notes, so make it clear and concise.
